# WorkStyle construct audit 10 — Gap review after reduction

Status: ARCHITECTURE GAP AUDIT / PRE-ITEM-WRITING
Date: 2026-08-23
Branch: hero-webgl

## Purpose

After removing / merging weak inherited constructs, test whether the reduced architecture has obvious content gaps that justify introducing entirely new constructs before item writing.

Candidates raised during independent review:
- pace / tempo;
- conflict engagement;
- detail ↔ gist processing.

Rule:
**A gap is not automatically a dimension.** New constructs require a clear behavioural space, non-redundancy, and relevance to the product's purpose.

---

## 1. Pace / Tempo

Possible construct:

`Deliberative pace ↔ Rapid action pace`

### Why it is attractive

- intuitively relevant across many kinds of work;
- potentially neutral: speed and deliberation both have benefits;
- distinct from Structure in principle;
- distinct from Social Energy.

### Main problems

Pace is highly constrained by:
- task urgency;
- error cost;
- role authority;
- workload;
- expertise.

Without careful contexts, responses may measure whether the respondent understands that some tasks require speed and others require care.

It may also overlap with:
- risk scanning;
- method adaptation;
- cognitive ability / confidence.

### Decision

**PARK as NEW-CANDIDATE, not admitted to V1 core yet.**

It is promising enough for later cognitive exploration, but there is no evidence that the current architecture needs it before the existing axes are validated.

---

## 2. Conflict Engagement

Possible construct:

`Engage disagreement ↔ Avoid / defer disagreement`

### Why it is attractive

Conflict behaviour is highly relevant to work and leadership.

### Redundancy problem

The reduced architecture already includes:

`Position Assertion ↔ Accommodation`

That axis explicitly covers behaviour when opinions, priorities or interests differ.

A separate conflict-engagement axis would likely split:
- whether one enters the conflict at all;
- how one behaves once engaged.

This is conceptually possible, but for a compact reflection tool it risks creating another pair of highly correlated interpersonal scales.

### Decision

**DO NOT ADD as a separate V1 core construct.**

Use conflict as an item context / scenario facet for Position Assertion ↔ Accommodation.

Revisit only if cognitive testing shows a clear class of people who:
- readily raise disagreement but then accommodate;
- avoid raising disagreement despite otherwise assertive communication.

Until then the extra score is not justified.

---

## 3. Detail ↔ Gist processing

Possible construct:

`Detail focus ↔ Big-picture / gist focus`

### Why it is attractive

It is easy to understand and potentially non-evaluative.

### Redundancy problem

The emerging `Local / concrete focus ↔ System / relational focus` construct already occupies nearby cognitive territory.

They are not identical:
- detail/gist concerns granularity;
- local/system concerns relational breadth and dependencies.

However ordinary respondents may not reliably separate them in short workplace items.

Keeping both before evidence would likely recreate the exact redundancy problem the redesign is intended to solve.

### Decision

**DO NOT ADD as a separate V1 core construct.**

During Level-of-Analysis item development, tag item content for:
- granularity;
- relational breadth.

If the data later split them, Detail↔Gist can become a future construct.

---

## 4. Gap-audit conclusion

No new construct is required before the next item-development stage.

### Parked research candidate
- Pace / Tempo.

### Not added because of current redundancy
- Conflict Engagement → covered as context within Position Assertion;
- Detail ↔ Gist → monitored within Level of Analysis.

This is intentionally conservative.

The reduced architecture should first prove that its existing constructs are comprehensible and separable before adding new dimensions for completeness.

---

## 5. Product-coverage principle

WorkStyle does not need to measure every meaningful work behaviour.

A smaller profile is preferable when each axis answers a distinct, explainable question.

The product can later expand only when:
- users repeatedly perceive a missing part of their work style;
- cognitive interviews identify a coherent uncaptured tendency;
- or empirical data reveal a stable factor not represented by the current blueprint.
