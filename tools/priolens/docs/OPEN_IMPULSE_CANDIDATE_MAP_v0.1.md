# PrioLens open impulse candidate map v0.1

Status: ACTIVE DISCOVERY MAP / NOT FINAL TAXONOMY
Date: 2026-08-31

## Purpose

Turn the broader impulse discussion into one compact working map before another stimulus bank is built.

This map combines three things without treating any of them as final truth:

1. coarse need-domain coverage inspired by Maslow-style layers;
2. impulse families already visible in the 223-image Gallery audit;
3. theoretically important gaps exposed by AgileBrain and broader motivation frameworks.

The macro domains are **coverage buckets**, not a hierarchy and not mutually exclusive psychological levels.

## Decision statuses

- `VISUAL_NOW` — multiple existing Gallery exemplars already make the pull readable enough to continue testing.
- `VISUAL_TEST` — plausible family, but current exemplars are partial, confounded or too narrow; worth a targeted visual viability test.
- `REFLECTION_HOLD` — important need/value area, but a single static image may require too much story or abstraction. Keep it in the perceived-sufficiency/reflection layer unless a convincing visual operationalization emerges.
- `SPLIT_TEST` — an old family appears to contain more than one distinct pull and should not be forced back together.

These are product-research decisions, not claims about which human needs are real.

## Important splits exposed by this map

### CON should not remain one undifferentiated social family

The current Gallery supports at least:
- direct connection / reciprocity;
- belonging / togetherness.

CARE is not yet represented and must not be backfilled with warm social scenes.

### PRO / INF / CER historically absorbed CONTROL

Flow routing, state switching, gates and access restriction repeatedly produce a concrete pull around **setting what happens next**. This is different enough from simple protection and from wider-system effect to deserve its own candidate family.

### OPP currently mixes at least two pulls

- `something rewarding/useful is available now`;
- `there is an open possibility I could develop/use`.

That is Resource/Reward vs Opportunity/Possibility. Do not force them together before testing.

### MAS is not the same as SUCCESS

Mastery is about quality/skill in the act. Achievement is about reaching an outcome/standard. The current bank visually supports mastery much better than achievement.

## Two-channel architecture consequence

Not every meaningful need area must become a visual stimulus family.

The current working architecture can legitimately have:

### Channel A — visual priority

Use families that can produce vivid, quickly readable, competing scenes without requiring a paragraph of hidden story.

### Channel B — perceived sufficiency / reflection

Cover broader human-need areas, including important domains that may be too abstract for reliable single-static-image representation.

Therefore `REFLECTION_HOLD` is **not a failed construct**. It means only:

> do not damage the visual task by forcing an abstract value into a weak picture.

This is currently the preferred stance for Justice/Fairness and Purpose/Meaning.

## Next move

Do not generate a broad new library.

Run a **targeted visual viability probe** only for the families where the spectrum matters and static imagery still looks plausible:

1. Care / caregiving;
2. Recognition / esteem;
3. Achievement / success;
4. Authenticity / self-expression;
5. Contribution / service;
6. optionally Immersion / engagement.

For each family, first define 2 materially different everyday scene mechanisms in words. The scene passes only if the intended pull can plausibly be the first read without text or hidden backstory.

Do not generate images until those mechanisms are judged worth trying.

Justice/Fairness and Purpose/Meaning stay in `REFLECTION_HOLD` for now rather than being forced into visual imagery.
