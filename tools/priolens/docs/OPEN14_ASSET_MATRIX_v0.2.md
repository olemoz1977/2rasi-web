## v0.1 -> v0.2 changes

### SUCCESS removed

`SUCCESS` is no longer an Open14 atomic family.

It remains `DERIVED / THEORY-HOLD` because the visible attraction to a successful outcome can come from mastery, recognition, reward/resource, control, autonomy or opportunity.

### BELONGING added from existing Gallery

BELONGING does not create a new asset gap.

Selected candidates:
- `S14.webp` — active group/social-circle scene;
- `20260731_043300801.png` — shared warmth / togetherness.

Why these two:
- they are materially more group/togetherness oriented than `S03`;
- they do not depend on the same object-passing reciprocity mechanism as CONNECTION-B;
- their first-impulse records already existed before the BELONGING decision.

Known ambiguity:
- `S14` can still read as generic social interaction;
- shared warmth carries positive valence.

Keep and test. Do not sterilize solely to eliminate every secondary reading.

### CARE narrowed

CARE remains blank because the old warm/together scenes are now correctly used for CONNECTION/BELONGING rather than relabeled as caregiving.

Accepted mechanism space:

**CARE-A — visible self-cost**
- voluntary action for another's welfare;
- small visible loss of own comfort/resource;
- avoid heroic danger.

**CARE-B — proactive help without request**
- person notices another struggling;
- begins practical help without a visible request;
- scene should remain understandable without hidden story.

### KNOWLEDGE-B changed

Old v0.1 pair:
- explicit classroom;
- explicit information-access scene;
- both portrait sources.

P3 uses square `object-fit: contain` image areas, so representing one family with two portrait images risks a family-level size/salience disadvantage.

v0.2 keeps:
- A = explicit learning/classroom;
- B = square `20260811_180451129.png`, first read `pamatyti aiškiau / daugiau`.

This is deliberately a **Learning / Understanding boundary probe**.

Do not claim that perceptual clarity and knowledge are already proven to be one family. Exemplar identity remains mandatory in analysis.

Reserve explicit knowledge-access scene:
- `20260730_233054250.png` — `ieškoti žinių / prieiga prie informacijos`.
